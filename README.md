# «Кильватер» — ночной морской чат

Чат ко Дню ВМФ: участники — корабли, дело происходит ночью, в шапке живая сцена спокойного
моря под луной. Когда кто-то печатает, его корабль передаёт сигнальной лампой азбукой Морзе.

## Настройка проекта

```bash
# Install dependencies
npm i

# Start dev server (localhost:3000)
npm run dev
```

Без настроек Firebase приложение работает на эмуляторе бэкенда (localStorage) и входит
«местным» — так и идут проверки и разработка без сети. Чтобы поднять его на настоящем
Firestore, нужен `.env.local`:

```bash
VITE_BACKEND=firebase
# Либо настоящий проект — настройки из консоли Firebase (Project settings → Your apps),
VITE_FIREBASE_API_KEY=…
VITE_FIREBASE_AUTH_DOMAIN=…
VITE_FIREBASE_PROJECT_ID=navy-chat
VITE_FIREBASE_APP_ID=…
# либо локальные эмуляторы, которым ключи не нужны вовсе:
VITE_FIREBASE_EMULATOR=1
```

Эмуляторы поднимает `npm run functions:dev` (Auth, Firestore и функции). Что за коллекции
и правила за этим стоят — в [docs/FIREBASE.md](docs/FIREBASE.md).

## Firebase с нуля

Порядок действий на свежем аккаунте: что завести в консоли, что раскатать из репозитория
и чего нельзя переиграть потом. Устройство — коллекции, правила, функции — в
[docs/FIREBASE.md](docs/FIREBASE.md); здесь только последовательность.

Всё это нужно ради общей базы и настоящего входа. Без Firebase приложение работает на
локальном бэкенде и входит «местным» — так идут разработка и проверки.

### 1. Проект и тариф

Консоль → **Add project**. Google Analytics не нужен.

Дальше **сразу на Blaze** (Upgrade в левом нижнем углу): на Spark нет Cloud Functions, а на них
стоит вся расстановка на рейде — без функций нельзя ни встать в строй, ни уйти. Blaze — счёт
по факту, и бесплатная часть в нём та же, что и на Spark: 50 000 чтений и 20 000 записей
в сутки, два миллиона вызовов функций в месяц. Чат ко Дню ВМФ укладывается в неё с запасом.

Предел трат поставьте сразу, пока помните: Google Cloud Console → Billing → **Budgets &
alerts**. Blaze без бюджета — счёт без потолка, а ошибка в подписке тратит деньги молча.

### 2. База: локацию выбирают один раз

Firestore → **Create database**. Редакция — **Standard**, имя базы — **`(default)`** (так
записано в [`firebase.json`](firebase.json), другую приложение не найдёт), режим —
**Production mode**: правила приедут из репозитория следующим шагом, а Test mode на месяц
открывает базу всем на запись.

**Локация меняется только вместе с базой.** Переехать нельзя — можно завести вторую базу
и перелить данные. Поэтому:

- В репозитории уже выбран **`europe-central2` (Варшава)** — `firestore.location`
  в [`firebase.json`](firebase.json). Одиночный регион (дешевле мультирегиона на записи),
  из ближайших к тем, для кого чат.
- Регион функций **обязан совпадать** с регионом базы: `setGlobalOptions({ region })`
  в [`functions/src/index.ts`](functions/src/index.ts). Вход на рейд — это функция, гоняющая
  транзакцию в Firestore; разъедутся регионы — каждый вход поедет через океан.
- Берёте другую — правьте **оба** места. И сверьтесь с обоими списками: у Firestore и у Cloud
  Run (на нём живут функции второго поколения) наборы регионов разные.
- Мультирегион (`eur3`, `nam5`) чату не нужен: дороже на записи и не быстрее на чтении.

У входа (Authentication) региона нет вовсе, сайт лежит на GitHub Pages — тоже.

### 3. Вход

Authentication → Get started → **Google**, включить. Других провайдеров приложение не знает
([`src/backend/auth.ts`](src/backend/auth.ts) — только `GoogleAuthProvider`).

Authentication → Settings → **Authorized domains**: `localhost` там уже есть, добавьте домен,
с которого открывают сайт, — для этого репозитория `ipetropolsky.github.io`. Забытый домен
отказывает ровно на выкладке, где это труднее всего заметить: окно входа откроется и закроется,
а причина останется в консоли браузера — `auth/unauthorized-domain`.

### 4. Веб-приложение и переменные

Project settings → Your apps → **Add app → Web**. Firebase Hosting не подключать: сайт уезжает
на GitHub Pages. Storage тоже не нужен — приложение его не трогает, а `storageBucket` из конфига
берите как есть, он там для полноты.

Семь значений из **SDK setup and configuration → Config** идут локально в `.env.local`
(`cp .env.example .env.local`), а на выкладке — в переменные репозитория, см.
[«Переменные выкладки»](#переменные-выкладки) ниже.

### 5. Правила: из файла, а не копипастой

Правила лежат в [`firestore.rules`](firestore.rules), путь к ним — в `firebase.json`:

```bash
npx firebase login              # один раз
npx firebase use navy-chat      # свой project id; по умолчанию берётся из .firebaserc
npx firebase deploy --only firestore
```

`--only firestore` — это правила **и** индексы разом. Составных индексов пока нет
(`firestore.indexes.json` пуст), так что второе ничего не делает; появится запрос, которому
индекс нужен, — Firestore сам скажет какой, и он уедет туда же.

**Не вставляйте правила в консоль руками.** Вставить можно, работать будет — но с этой минуты
файл и консоль расходятся молча: следующий `deploy` затрёт правку из консоли, а следующая
правка в консоли переживёт правку в файле. Проверяются правила тоже как файл — `npm run
test:emulator` гоняет по нему [`firestore/rules.test.ts`](firestore/rules.test.ts), и того,
что стоит в консоли, эта проверка не видит вовсе.

Свежая база в Production mode запрещает всё, поэтому `403` и «Missing or insufficient
permissions» в ответ на любое чтение — это не поломка, а просто ещё не уехавшие правила.

### 6. Функции: без них не встать в строй

Не «по желанию». Правила **нарочно** запрещают клиенту писать рейд — участия, брони мест
и старшинство заводит серверный код (docs/FIREBASE.md, «Правила рейда живут на сервере»).
Делают это четыре вызываемые функции: `joinChannel`, `updateMember`, `leaveChannel`,
`kickMember`. Без них не работают вход на рейд, переоснащение, уход и высадка.

```bash
npm ci --prefix functions       # свои зависимости: из корня они не ставятся
npm run functions:deploy        # = firebase deploy --only functions
```

Первая раскатка дольше остальных и спрашивает разрешения включить сопутствующие службы
(Cloud Build, Artifact Registry, Cloud Run, Eventarc) — соглашайтесь, без них функции второго
поколения не собираются. Рантайм — Node 24 (`engines` в `functions/package.json`).

Правила и функции разом:

```bash
npx firebase deploy --only firestore,functions
```

### 7. Проверить, что встало

Открыть сайт, войти, завести канал, встать в строй, написать реплику. Если что-то не так,
отказ обычно называет себя сам:

| Что видно                                     | Что не сделано                                           |
| --------------------------------------------- | -------------------------------------------------------- |
| `403`, «Missing or insufficient permissions»  | Правила не раскатаны (шаг 5)                             |
| Окно входа открылось и закрылось              | Домен не в Authorized domains (шаг 3)                    |
| Канал открывается, но «встать в строй» падает | Функции не раскатаны (шаг 6)                             |
| Вход в строй ждёт и отваливается по таймауту  | Регион функций разъехался с регионом базы (шаг 2)        |
| Сайт цел, но без входа и без общей базы       | Сборка ушла на localStorage: нет `VITE_BACKEND=firebase` |

Демо-канал заводить не нужно: приложение работает и без него — кнопка ведёт на `?channel=demo`,
и если канала нет, человек видит обычное «канала нет». Скрипт `npm run seed:firestore` сидирует
**только эмулятор** и без `FIRESTORE_EMULATOR_HOST` отказывается запускаться нарочно
([`tools/seed-firestore.ts`](tools/seed-firestore.ts)).

### 8. Что раскатывается руками, а что само

| Что               | Чем                                    | Когда                                  |
| ----------------- | -------------------------------------- | -------------------------------------- |
| Правила и индексы | `npx firebase deploy --only firestore` | Руками, после правки `firestore.rules` |
| Функции           | `npm run functions:deploy`             | Руками, после правки `functions/src`   |
| Сайт              | `.github/workflows/deploy.yml`         | Само, на пуш в `master`                |

Воркфлоу **функции собирает, но не выкладывает**, а правил не касается вовсе: сборка там нужна
затем, чтобы поломка `functions/src` не дожила до раскатки незамеченной. Правила и функции
выкатывает человек — и помнит об этом сам.

## Сборка и деплой

```bash
# Production build to /build
npm run build
```

Сборка попутно кладёт в `/build` манифест и service worker — приложение можно установить
на телефон как обычное; подробности и то, что service worker нарочно не кэширует, —
в [docs/PWA.md](docs/PWA.md).

Выкладывает на GitHub Pages не команда, а `.github/workflows/deploy.yml`. Сам он срабатывает
на пуш в `master`; в остальных случаях — **Actions → Build & Deploy to GitHub Pages →
Run workflow**, ветка выбирается там же. Своей команды для этого нет нарочно: настройки
Firebase лежат в переменных репозитория, и сборка с машины взяла бы чужие или не взяла
никаких. Меняли переменную — перезапустите воркфлоу руками: сам он на это не просыпается,
а выложенной остаётся сборка со старыми значениями.

### Переменные выкладки

Settings → Secrets and variables → Actions → вкладка **Variables**, семь штук. Значения —
в консоли Firebase: Project settings → Your apps → веб-приложение → SDK setup and
configuration → Config.

| Переменная                          | Значение                                |
| ----------------------------------- | --------------------------------------- |
| `VITE_BACKEND`                      | `firebase`                              |
| `VITE_FIREBASE_API_KEY`             | из консоли                              |
| `VITE_FIREBASE_APP_ID`              | из консоли                              |
| `VITE_FIREBASE_AUTH_DOMAIN`         | из консоли (`<проект>.firebaseapp.com`) |
| `VITE_FIREBASE_PROJECT_ID`          | из консоли                              |
| `VITE_FIREBASE_STORAGE_BUCKET`      | из консоли                              |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | из консоли                              |

Секретами их назначать незачем: всё, что начинается на `VITE_`, уезжает в бандл к каждому,
кто откроет страницу. Секрет их не спрячет, а в логе сборки замажет звёздочками. Воркфлоу
всё же смотрит в обе вкладки (`vars.X || secrets.X`) — чтобы перепутанная не стоила красной
выкладки.

`VITE_FIREBASE_EMULATOR` на выкладке **не задавать**: он увёл бы живой сайт на `127.0.0.1`.
Без `VITE_FIREBASE_API_KEY` и `VITE_FIREBASE_APP_ID` сборка при `VITE_BACKEND=firebase`
откажется собираться — это нарочно, иначе на Pages молча уезжает версия на localStorage,
без входа и без общей базы. Подробности — в [FIREBASE.md](docs/FIREBASE.md),
«Конфигурация и запуск», и в [`.env.example`](.env.example).
