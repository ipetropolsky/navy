## Привести контракт бэкенда к принципам API

**Зачем.** Принципы записаны в [API-PRINCIPLES.md](./API-PRINCIPLES.md), нынешний контракт
им следует не целиком. Пока фронтенд один и бэкенд эмулируется, цена правки — переименования
в десятке файлов. Чем позже, тем дороже: контракт разойдётся по чужим клиентам.

**Что править** — полный разбор в разделе [«Что не так и требует
приведения»](./API-PRINCIPLES.md#что-не-так-и-требует-приведения). Кратко:

- `ChannelSnapshot` → `{ channel, members, messages }`, поля канала не вперемешку с коллекциями;
- идентификаторы сущностей переименовать в `channelId` / `memberId` / `messageId` / `eventId`,
  чтобы ссылка и сущность назывались одинаково;
- ссылки завернуть в объекты: `author: { memberId }`, `thread: { messageId }`,
  `member-left { member: { memberId } }`, `typing { member: { memberId }, typing: { chars } }`;
- методы перевести на один именованный объект: `setTyping({ channelId, memberId, typing })`;
- ответы завернуть: `join` → `{ member }`, `sendMessage` → `{ message }`;
- `channel-updated` → `{ channel }` целиком вместо плоских `slug` и `title`;
- `corridor` и `tried` — на перечисление `'left' | 'center' | 'right'`;
- завести именованный `Side` вместо повторяющегося `'left' | 'right'`;
- в `MessageDraft` оставить тело сообщения, отправителя передавать параметром.

**Что заденет.** `src/backend/types.ts`, `localBackend.ts`, `placement.ts`, `seed.ts`,
`src/types/channel.ts`, `useChannel.ts`, `App.tsx` и компоненты сцены и ленты. Правка
механическая: типы поймают все места.

**Про хранилище.** Форма хранимого состояния меняется, а значит по правилу [«К чужим данным —
бережно»](./BACKEND-API.md#к-чужим-данным--бережно) к этому моменту нужна миграция, а не
сброс: прочитать старую форму, привести к новой, записать. Если правка успеет пройти
до первого живого канала, хватит и подъёма версии.

## Миграции хранилища вместо сброса

Сейчас несовпадение `STORAGE_VERSION` стирает состояние и записывает демо-канал заново.
Это осознанная поблажка фазы разработки. До того, как в канале заведётся первый настоящий
разговор, на этом месте должна появиться миграция: по функции на переход версии, каждая
достраивает недостающее и ничего не удаляет. Правило — в
[BACKEND-API.md](./BACKEND-API.md#к-чужим-данным--бережно).
