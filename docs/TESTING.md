# Проверки

Набор сценарных проверок в настоящем браузере — Playwright, папка [`tests`](../tests),
настройки в [`playwright.config.ts`](../playwright.config.ts). Половина этого приложения
проверяется только замером в кадре: совпадают ли кадры воды на стыке цикла, помещаются ли
корабли на телефоне, доезжает ли сообщение во вторую вкладку, — поэтому проверки здесь
не юнитовые, а сценарные, и гоняются в браузере.

Собирать проект и поднимать сервер руками не нужно: конфиг сам собирает сборку и поднимает
`vite preview` на порту 4173. На новой машине нужен один разовый шаг — `npx playwright install
chromium`. Если Chromium уже стоит и качать его незачем, путь к нему передаётся переменной
`PLAYWRIGHT_CHROMIUM_PATH`.

## Гонять

```bash
npm run test:e2e                                   # весь набор
npm run test:e2e -- tests/scene.spec.ts            # один файл
npm run test:e2e -- tests/scene.spec.ts:160        # один тест — по строке, где он объявлен
npm run test:e2e -- -g "уступает воду"             # один тест — по куску названия
npm run test:e2e -- -g "телефон"                   # и целая группа: describe тоже ищется
```

Двойное тире обязательно: без него флаги достанутся `npm`, а не Playwright.

Полезное рядом:

```bash
npm run test:e2e -- --repeat-each=5 -g "..."       # пять прогонов подряд: ловим мигание
npm run test:e2e -- --workers=1                    # по одному: медленнее, зато не мешают друг другу
npm run test:e2e -- --retries=2                    # с повторами, как на CI
```

Можно и `test.only` — но только у себя: на CI такой набор не пройдёт вовсе (`forbidOnly`),
и это нарочно, чтобы забытая пометка не превратила весь набор в одну проверку.

## Смотреть глазами

По умолчанию браузер идёт без окна: так быстрее, и на CI иначе нельзя. Когда нужно увидеть,
что происходит:

```bash
npm run test:e2e -- --headed -g "..."              # окно браузера, всё как у человека
npm run test:e2e -- --ui                           # режим наблюдения: список, кадры, время
```

`--ui` — самое полезное из двух. Он открывает своё окно со списком проверок: любую можно
запустить, отмотать по шагам, увидеть кадр до и после каждого действия, посмотреть, что в этот
момент было в DOM, и подобрать локатор тыком в элемент. Правки в файлах он подхватывает сам
и перезапускает проверку.

Окно браузера с `--headed` стоит держать в паре с `--workers=1` и одной проверкой: иначе окон
будет столько, сколько параллельных потоков, и уследить за ними не выйдет.

## Отлаживать

```bash
npm run test:e2e -- --debug -g "..."               # инспектор: шаг за шагом, браузер не закрывается
PWDEBUG=1 npm run test:e2e -- -g "..."             # то же самое переменной
PWDEBUG=console npm run test:e2e -- -g "..."       # devtools браузера, playwright доступен в консоли
```

`--debug` открывает Playwright Inspector: проверка встаёт на первом же действии, дальше её
ведут кнопкой «шаг», а браузер остаётся открытым после конца — можно спокойно лазить по DOM
и по консоли. Таймауты в этом режиме отключены, и зависнуть над одним шагом можно сколько
угодно.

Точка останова посреди проверки ставится прямо в коде:

```ts
await page.pause(); // проверка встаёт здесь и ждёт, окно браузера остаётся живым
```

Брейкпоинты в коде самого приложения ставятся в devtools открытого браузера — исходники
на месте, sourcemaps тоже. Проще всего так: `PWDEBUG=console`, в консоли браузера поставить
брейкпоинт, дальше шагать инспектором.

Отладчик редактора тоже работает: в VS Code с расширением Playwright брейкпоинты ставятся
прямо в `.spec.ts` и ловятся при запуске из редактора.

## Разбирать упавшее

Локально репортер — `list`: видно каждую проверку и то, на какой строке она упала. Что ещё
можно попросить:

```bash
npm run test:e2e -- --reporter=html && npx playwright show-report   # отчёт страницей
npm run test:e2e -- --trace on -g "..."                             # трасса всегда, а не только на повторе
npx playwright show-trace test-results/<папка>/trace.zip            # и её просмотр
npm run test:e2e -- --last-failed                                   # только то, что упало
DEBUG=pw:api npm run test:e2e -- -g "..."                           # каждый шаг Playwright строкой в консоль
```

Трасса — самое подробное из всего: в ней кадры до и после каждого действия, DOM целиком,
сеть и консоль. По умолчанию она пишется только при повторе упавшей проверки (`on-first-retry`),
а повторы включены лишь на CI, — поэтому локально её просят руками. Видео и отдельные снимки
экрана флагами не включаются: это настройки `use` в конфиге (`video`, `screenshot`), и заводить
их обычно незачем — в трассе кадр каждого шага уже есть.

Папки `test-results` и `playwright-report` в гите не лежат: это следы прогона, а не проект.

## Быстрый круг

Каждый прогон начинается со сборки — это секунд двадцать сверх самой проверки. Когда правишь
одну проверку и гоняешь её раз за разом, сервер стоит поднять самому: если на 4173 уже кто-то
слушает, Playwright возьмёт его и собирать не станет (`reuseExistingServer`).

```bash
npx vite --port 4173 --strictPort        # в отдельном окне: dev-сервер с горячей перезагрузкой
npm run test:e2e -- -g "..."             # и прогон без сборки
```

Замер на этом наборе: с пересборкой один тест проходит за полминуты, с поднятым dev-сервером —
за пять секунд, и правки в коде приложения подхватываются без перезапуска. Перед тем как
считать работу сделанной, набор всё-таки надо прогнать обычным способом: на dev-сервере код
не минифицирован и собран иначе, чем то, что уедет на Pages.

## Чтобы не мигало

Проверки здесь ходят по анимированной сцене, и главный источник мигания один: замер снят
раньше, чем случилось то, что меряют.

- **Ждать следствие, а не время.** `waitForTimeout` годится там, где ждать нечего — например,
  пока корабль доедет до места, — и не годится вместо признака. Признак лучше: `toBeVisible`,
  `toHaveCount`, `toContainText` сами ждут и сами повторяют замер.
- **Для движения — `expect.poll`.** Он перемеряет, пока не сойдётся: так проверяются размеры
  подсветки, фаза качки, возвращение корабля на своё место.
- **Щелчок по тому, что может уехать, подтверждать признаком.** На этом уже стояли: лента
  прыгает к последнему сообщению сама, и щелчок по верхнему пузырю приходился ровно на прыжок —
  реплика уходила без привязки, а падала проверка строкой ниже и совсем про другое. Лечится
  ожиданием цитаты над строкой ввода: пока её нет, вкладка ещё не знает, на что отвечает.
- **Свой канал вместо демо, когда важна расстановка.** В демо-канале места раздаёт случай,
  и попадётся ли нужная линия — как повезёт. Проверки про геометрию заводят свой канал и ставят
  соседа туда, куда нужно.
- **Проверять мигание прогоном.** `--repeat-each=5` на одной проверке ловит его быстрее, чем
  третий подряд зелёный набор.
